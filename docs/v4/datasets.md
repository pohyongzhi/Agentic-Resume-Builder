# Dataset evidence and selection

Research date: 24 October 2026. Sizes below are publisher/paper/viewer reports, not counts from a locally downloaded and audited corpus. Counts can differ by release and language filtering. Source labels describe declared licenses; they do not independently clear underlying third-party material. Every candidate is assessed for English Qwen3.5-4B resume-tailoring SFT, with academic use and future extension in mind.

## Final ranking and practical decision

| Rank | Recommendation | Why / limits |
|---|---|---|
| 1 | Newly authored fictional source resumes and independently constructed JDs, with new evidence-checked tailored targets | Best control over candidate truth, chronology, privacy, sparse inputs and Singapore context. Human validation and varied styles are essential; synthetic polish alone is not realism. |
| 2 | Selected Djinni English candidate profiles and JDs | Strongest inspected real-source option: platform-supplied corpus, paper and cards state MIT, documented privacy processing. Admit only records passing new privacy and factual-completeness checks. Tech/Ukraine bias and missing conventional resume sections prevent it from defining the entire corpus. |
| 3 | O*NET / ESCO | Licensed occupation/skill references for coverage and synthetic JD authoring. They do not establish any candidate's qualifications and are not rewrite targets. |
| 4 | USAJOBS public API data as a small optional JD slice | Current terms support broad public-data reuse; federal eligibility and prose differ from the project's main audience. Do not build the entire corpus around it. |
| 5 | Candidate-matching-synthetic, and conditionally RJDB | Useful structural references or optional source seeds. Matching labels and matched/unmatched triples must never be used as rewrite truth. |
| Reserve | Open Jobs; demonstrably synthetic datasetmaster records | Potential breadth after resolving the particular source/provenance questions. The initial project can proceed without them. |
| Auxiliary evaluation | JobResQA; SkillSpan for skill extraction if its exact release is verified | Distinct tasks and retained attribution. Keep evaluation examples out of SFT and separate calibration subsets from reported test subsets. |

Proposed 5,000-example input mix: **80% newly authored fictional resumes (including 5 percentage points of noisy/robustness cases), 20% admitted Djinni profiles**. Proposed JD mix: **55% independently authored, 35% admitted Djinni, 10% USAJOBS**. If USAJOBS access is unavailable, replace its slice with authored JDs. If Djinni admission fails, use the fully fictional route and report the realism limitation. At least 20% of cases should be independently authored Singapore-context examples. Percentages are trial design choices to revisit on development data, not empirically established optima.

### Adjudication of competing recommendations

The initial resume review favoured Djinni as the main corpus; the initial JD review favoured USAJOBS. Cross-source review instead gives fictional source facts the majority because many profiles lack education/employment detail and government ads introduce domain skew. The desired target is faithful rewriting, which none of these raw corpora directly supplies. This ranking puts task fit and verified source evidence ahead of row count.

Three source-category reviews were followed by a separate licensing review, synthetic-design review and cross-source challenge. The cross-source reviewer also authored the JD inventory, so this is not a wholly blind independent judging process. The final synthesis rechecked disputed claims against primary sources. A fresh independent final adjudication remains pending and has not approved this report. A separate evidence-aware human audit remains part of the pilot gate; no reviewer score is presented here as measured model performance.

One material correction was resolved: an older cached USAJOBS result showed restrictive terms, whereas fresh opens of both current official URLs showed the public-data reuse grant. Use the fresh terms, capture the version at acquisition, and retain separately restricted-item exceptions. SFT eligibility is an inference from the broad lawful-use grant, not an explicit model-training clause. [Current USAJOBS terms](https://developer.usajobs.gov/apirequest/)

## Admission and release rules

Use the clearly documented sources with ordinary provenance/privacy checks; no blanket external approval process is imposed. Escalate only a specific unresolved source if it is necessary. Separate local research, sending data to a teacher service, redistributing derived datasets and publishing weights: permission for one is not automatically permission for every other use. Academic status alone does not settle these questions.

Capture source/version/license/notice, exact source lineage, privacy processing and purpose in a manifest. Remove names/contact information and sensitive irrelevant attributes without changing candidate qualifications. Preserve a protected raw-to-clean mapping only where needed and permitted. Never put real contact data into prompts or Git merely because it was publicly accessible.

Synthetic paraphrasing does not erase source restrictions. Do not relabel all mixed-source rows MIT. Keep attribution and applicable share-alike obligations with distributed data; assess any future model-release obligations separately. This workstream currently keeps research and code local and performs no publication.

The [training plan](training-plan.md) defines the actual target generation, evidence maps, rejection process, grouped splits and benchmark isolation. None of these sources overrides the requirement that every target claim must be supported by its original resume.
